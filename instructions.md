# Motherly+ RCT3 — Pre-Specified Statistical Analysis Plan

## 1. Overview

Parallel-group randomized controlled trial (RCT) testing the efficacy of **single-session psychotherapy supported by a smartphone app (Motherly)** for postpartum depression (PPD), compared to a **waitlist control** group.

- **Planned N**: 104 women (18–40 years old, up to 12 months postpartum, with major depressive disorder).
- **Arms**: 1 = Waitlist (control); 2 = Intervention.
- **Timepoints**: T1 (baseline, week 1), T2 (week 2), T3 (week 4, post-treatment), T4 (week 8, follow-up).

## 2. Outcomes

### Primary outcome
- QIDS-C16 total score at T3 (week 4).

### Secondary outcomes (T3 and T4, unless otherwise noted)
- QIDS-SR16 total score
- GAD-7 total score
- PSQI total score
- PSI-SF total and subscale scores (parental distress, parent-child dysfunctional interaction, difficult child)
- SDS total score
- EPDS total score
- CGI-I at T3

### Mediators (T1 and T2)
- BADS-SF total score
- RPI total score

### Moderators (baseline)
- Maternal age, race/skin color, education, income, number of children, marital status, social support (MSPSS), infant age, prenatal visits, baseline QIDS-SR16/QIDS-C16, baseline CGI-S, baseline SDS.

### Treatment-specific processes
- Therapeutic alliance (WAI-SR client and therapist versions) at T2.
- App engagement metrics (Motherly app usage) — data not yet available; placeholder for future analysis.

## 3. Main analytical strategy

- **Intention-to-treat (ITT)**: all randomized participants are analyzed according to allocated group.
- **Models**: generalized estimating equations (GEE) with first-order autoregressive correlation structure (AR1) and robust sandwich standard errors.
- **Specification**: `outcome ~ group * time`, with `group` and `time` as categorical factors.
- **Contrasts**: pairwise intervention vs. control comparisons at each timepoint, adjusted by Benjamini-Hochberg (FDR).
- **Effect size**: Cohen's d derived from marginal means and observed standard deviations.
- **Significance**: p < 0.05; 95% confidence intervals for all parameters.

## 7. Operational dashboard (separate component)

The `dashboard/` directory contains a Quarto-based operational dashboard that is **independent** of the pre-specified analysis scripts. It is not part of the inferential analysis plan and must not be cited as such.

### Purpose and scope
- **Purpose**: monitor recruitment, randomization, assessment completion, follow-up windows, and clinical/operational alerts during trial execution.
- **Scope**: descriptive counts, percentages, and status flags. No hypothesis tests, no effect sizes, no adjusted models.
- **Target audience**: study coordination team, not the scientific reader of the final report.

### Data flow
1. Reads the latest REDCap CSV export from `data/trial/`.
2. Optionally reads the REDCap DataDictionary from `data/trial/` to group fields by instrument/form.
3. Saves derived RDS files to `dashboard/data/`.
4. Generates one `.qmd` per participant in `dashboard/participantes/` from `dashboard/template/participante_template.qmd`.
5. Renders the static site to `dashboard/_site/` via Quarto.
6. Publishes the site to InfinityFree via FTP (credentials stored with `keyring`).

### Independence rules
- `scripts/` never write to `dashboard/data/`, `dashboard/participantes/`, or `dashboard/_site/`.
- `dashboard/R/` never writes to `outputs/` or modifies analytic datasets used by `scripts/`.
- Both components share **only** the raw REDCap CSV in `data/trial/` (and `data/app/` in the future).

### How to update
```r
source("dashboard/R/atualizar_dashboard.R")
```

See `dashboard/README.md` and `dashboard/PROJETO_HANDOFF.md` for setup, business rules, and publishing details.

## 8. Important notes

- Randomization is performed by an independent statistician in REDCap; the analysis scripts do **not** randomize.
- REDCap data are exported in long format (`record_id` + `redcap_event_name`).
- The current preliminary dataset includes only T0–T3; T4 will be added when collected.
- Scripts must be reproducible from the exported REDCap CSV.
- The `dashboard/` component is independent of `scripts/`; it uses the same raw `data/trial/` CSV but writes derived files only to `dashboard/data/`. It must not be used for inferential analyses.

## 9. Items requiring verification

The following implementation details in the analysis scripts were written as placeholders or based on assumptions and **must be verified against the final REDCap data dictionary and official instrument scoring keys** before running the analyses:

1. **PSI-SF scoring**: The current subscale and total score calculations assume the 36 PSI-SF items are ordered 1–36 in the REDCap instrument and mapped to the PSI-4 variable names (`t1_psi10`, `t1_psi12`, `t1_psi13`, `t1_psi14`, `t1_psi17`, `t1_psi18`, `t1_psi19`, `t1_psi20`, `t1_psi23`, `t1_psi24`, `t1_psi26`, `t1_psi31`, `t1_psi32`, `t1_psi34`, `t1_psi36`, `t1_psi38`, `t1_psi41`, `t1_psi42`, `t1_psi44`, `t1_psi47`, `t1_psi50`, `t1_psi56`, `t1_psi58`, `t1_psi63`, `t1_psi64`, `t1_psi69`, `t1_psi70`, `t1_psi72`, `t1_psi73`, `t1_psi76`, `t1_psi80`, `t1_psi85`, `t1_psi91`, `t1_psi92`, `t1_psi93`, `t1_psi100`). Reverse-coded items are assumed to be `t1_psi58` (item 22), `t1_psi41` (item 32), and `t1_psi42` (item 33). This reverse-coding assumption must be verified against the official Brazilian PSI-SF manual before analysis; if REDCap already stores items in the stress direction, the `rev5()` transformation must be removed.- **Dashboard variable mapping**: The dashboard (`dashboard/R/preparar_dados.R`) uses heuristic field-name patterns (`t0_idade`, `t1_cor`, `t1_qidssr16_total`, `t1_qidsc16_total`, `t1_total_epds`, `t1_gad7`, `t1_badssf_total`, `t1_total_rpi`, `t3_total_sus`, etc.). These must be verified against the final REDCap export; mismatches will cause missing values in the dashboard without stopping the script.2. **PSQI scoring**: The total score is computed using the official 7-component algorithm (Buysse et al., 1989). Implementation assumes REDCap Likert items are coded 1–4 (shifted to 0–3) and that Q1/Q3 are stored as "HH:MM". Verify REDCap value labels and time formats before analysis.
3. **WAI-SR scoring**: The analysis uses the REDCap-derived subscale scores for client (`t2_waisrc_goals`, `t2_waisrc_tasks`, `t2_waisrc_bond`) and therapist (`t2_waisrt_goals`, `t2_waisrt_tasks`, `t2_waisrt_bond`). Verify that these are the official WAI-SR subscales and that directionality is correct.
4. **BADS-SF and RPI**: The scripts use REDCap totals `t1_badssf_total` and `t1_total_rpi`. Verify these are correctly computed.
5. **Sociodemographic recoding**: Codes for race (`t1_cor`), education (`t1_escola`), marital status (`t1_ecivil`), employment and other categorical variables were assumed. Final codes from REDCap must be confirmed.
6. **Group allocation**: The variable `rand_number` was assumed to hold the allocation code. The final variable name and codes must be confirmed once randomization is completed.
7. **CGI-I values**: The variable `t3_cgi_i` is used. Confirm directionality as 1 = very much improved to 7 = very much worse.
8. **QIDS item 12 (suicidality)**: The scripts use `qidsc16_12` and `qidssr16_12` extracted from the long dataset, plus clinical fields `pron_ideacao`, `enc_1___2`, `enc_1___3`, and `dropout7`. Verify these variable names and thresholds in the final REDCap export.
9. **App usage data**: The folder `data/app/` is reserved for Motherly app engagement data, but the export is not yet available. Scripts `01_load-app.r`, `04_process-app.r`, and `06_merge-trial-app.r` handle app data so that `22_process-analysis.r` can use app engagement metrics.
