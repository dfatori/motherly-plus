# Motherly Plus RCT

This repository contains two independent components for the **Motherly Plus** randomized clinical trial, a study designed to test a single-session psychotherapy supported by a smartphone app (Motherly) for postpartum depression.

1. **`scripts/`** — Pre-specified statistical analysis scripts for the RCT;
2. **`dashboard/`** — Operational dashboard.

## Requirements

- R >= 4.2
- R packages used by the analysis scripts (installed on first run if needed): `tidyverse`, `here`, `geepack`, `emmeans`, `multcomp`, `broom`, `psych`, `mediation`, `processR` or equivalent (see individual scripts for `library()` calls).
- For the dashboard: [Quarto](https://quarto.org/docs/get-started/), plus R packages `dplyr`, `tidyr`, `ggplot2`, `knitr`, `curl`, `keyring`.

## How to run the analyses

1. Export REDCap data as **CSV with field names**;
2. Save the file to `data/trial/MotherlyRCT2025-Geral_DATA_YYYY-MM-DD_HHMM.csv`;
3. Save Motherly app usage data to `data/app/`;
4. Run all analysis scripts from the R console with the working directory at the repository root:

   ```r
   source("scripts/99_master-run.r")
   ```

All outputs are saved to `outputs/` with filenames prefixed by the script number that generated them (e.g., `10_qids_contrasts.csv` from `10_primary-outcome.r`).

## How to update the dashboard

1. Ensure the latest REDCap CSV is in `data/trial/`.
2. (Recommended) Place the REDCap DataDictionary in `data/trial/` so instrument-level completeness can be calculated.
3. From the R console at the repository root:

   ```r
   source("dashboard/R/atualizar_dashboard.R")
   ```

This prepares the data, generates per-participant pages, renders the Quarto site to `dashboard/_site/`, and uploads to the configured InfinityFree FTP host. See `dashboard/README.md` and `dashboard/PROJETO_HANDOFF.md` for full details.

## Key analysis plan

- **Primary analysis**: GEE for QIDS-C16 at T3 (`group × time`, AR1 correlation, robust sandwich SEs).
- **Secondary analyses**: GEEs for QIDS-SR16, GAD-7, SDS, EPDS, PSQI, PSI-SF, and ordinal regression for CGI-I.
- **Mediation**: Parallel mediation by BADS-SF and RPI.
- **Moderation**: Baseline sociodemographic and clinical moderators.
- **Process analysis**: Therapeutic alliance (WAI-SR) and app engagement.
- **Sensitivity**: Completers-only, baseline-adjusted, and unstructured correlation models.
- **Adverse events**: ≥30% increase in QIDS-16 or QIDS item 12 ≥ 2, plus clinical AE fields.

## Dashboard

The operational monitoring dashboard lives in `dashboard/` and is kept **strictly separate from the analysis scripts**. It reads the same raw REDCap CSV from `data/trial/` and writes its own derived RDS files to `dashboard/data/` and generated pages to `dashboard/participantes/`.

- **Purpose**: real-time operational monitoring of recruitment, randomization, assessment completion, follow-up windows, and clinical alerts.
- **Scope**: descriptive counts and status tracking only; no hypothesis testing, no effect estimation, no inferential analyses.
- **Independence**: the dashboard does not run `scripts/`, and `scripts/` do not generate dashboard pages.
- **Documentation**: see `dashboard/README.md` (setup and separation) and `dashboard/PROJETO_HANDOFF.md` (business rules and handoff notes).

## Data governance and privacy

- Never commit identifiable participant data, raw REDCap CSVs, app usage exports, or dashboard RDS files to version control. The `.gitignore` file already excludes `data/trial/*.csv`, `data/app/*`, `dashboard/data/*.rds`, `dashboard/participantes/*.qmd`, and `dashboard/_site/`.
- Dashboard pages contain sensitive health information; publish only behind access control (the production dashboard uses Apache Basic Auth on InfinityFree).
- Do not store FTP passwords, `.htpasswd` contents, or API tokens in the repository; the dashboard uses `keyring` for the FTP password.

## Important notes

- `scripts/` and `dashboard/` are independent: the dashboard does not run analyses, and the analysis scripts do not generate dashboard pages.
- The analysis scripts are written for pre-registration. Any post-hoc change must be documented in `instructions.md` Section 9 (change log) before the analysis is re-run for the final report.
- Several scoring implementations (PSI-SF, PSQI, WAI-SR, BADS-SF, RPI, CGI-I, QIDS item 12) are based on assumptions and must be verified against the final REDCap data dictionary and official instrument scoring keys. See `instructions.md`, Section 8.
- App usage data are not yet available; placeholder scripts (`01_load-app.r`, `04_process-app.r`, `05_codebook-app.r`, `06_merge-trial-app.r`) are included for future use.
